# 议题三 整改方案：先做深一块，史料先成表，世界由程序转（Claude 裁决，2026-11-13）

## 由来
项目主人转来一份扫仓库的整改方案（五个病根 + 七步 + 七个阶段），并御示：
「可以用哈佛库（我是自己玩游戏，不是商用，不侵犯版权）」
「我还想要唐末五代，三国两晋十六国南北朝，大小国家政权都要，妥善处理……信息少的国家怎么办，我高度看中历史真实性」

## 病根：采纳（Claude 复核过）
- 史料薄：内置每年在任真人只有个位到几十位（议题二已量过，数一致）。
- 模型管得太多、系统不咬合、验收空转、摊子太大：属实。

## 裁决
1. **采纳「先做深一块」**。玩法样板间先做**晚明（1573–1644）**：史料最厚（哈佛库这一段约两万一千人、六千九百条带年份的任职；1625 年一年能排出五百来位在任的人，现在只有十二位）。做到项目主人玩着满意再铺开。
2. **史料表同时铺到项目主人点名的各段**（只做表，不做新玩法）：
   - 晚明、唐末五代十国：以哈佛库为骨（唐末五代约六千人、四千七百条带年份任职），原文库（正史、通鉴、实录）补漏、核对。
   - 汉末三国、两晋十六国、南北朝：哈佛库这几段很薄（三国一百五十余人、两晋十六国四百五十人，几乎没有带年份的任职），**以原文库为骨**：正史本纪、列传、通鉴逐年摘任免，每条带出处（书、卷）。
   - **大小政权都要**：每个政权至少有：君主世系与年号、都城、存续起止、疆域大概、要紧文武（宰辅、诸王、大将、州镇长官）。
3. **史料少的政权怎么办**（项目主人问）——分四层，越往下越少用：
   - 甲：史书写明的（谁、何年、何官），照写，带出处。
   - 乙：史书没写年份、只写先后的，照先后排、照相邻的年份推，记为「推定」，记死，前后不矛盾。
   - 丙：这个政权该有的位子（照它的官制，多半是仿晋、仿汉的那一套），史书查不到是谁的：**空着，标「史阙」**，不硬编；只有玩家身边、剧情非用不可的小位子，才用虚构人物，标「虚构」，戏份低（照 R-221 御示）。
   - 丁：人口、兵力、钱粮：照地理志、同时代相邻政权、史书里的会战兵数推一个范围，后台记，界面照「兵力虚实」规矩显示估计数，不写成确数。
   - 绝不编：君主、年号、大战、亡国、篡位这类大事，只照史书。查不到的大事不写。
4. **模型退到两件事**：听懂玩家的话、把程序算定的结果写成文字。人名、官职、年龄、数字从表里出；调用点逐步从一百多处砍下来（样板间先做）。
5. **不推倒重写**：新的「史料表 + 按月运转的朝局」做成独立的一块，旧系统冻结不删；大文件趁着做样板间逐步拆。理由：一次重写风险太大，玩家会有很长时间没东西玩。
6. **验收改法**：采纳。真模型连玩三十回、正文人名官职年份对表；每个阶段交项目主人玩，说行才往下；没验过的阶段之上不加新功能。
7. **哈佛库用法**：原库（约六百兆）不进仓库，开发时下载、单独目录、只读；整理出来的表（人、生卒、官职、起止年、出处）进仓库，注明「数据出自哈佛中国历代人物传记资料库（CBDB），非商业用途」。

## 补裁（2026-11-13，项目主人定，R-227）
- 第 1 条改：样板间不做晚明，**先做五代十国（907–979）**；之后三国、两晋十六国、南北朝、唐末（875–907）。晚明暂不做。
- 第 3 条丙层改：史书没留名的位子**不再空着标「史阙」**，照该国实际用人来路（宗室、本族部落首领、当地大族、起家旧部）补人，标「虚构」，补一次记死、不和真人重名；真人永远优先。小国照小国的规模搭位子，不硬套大朝廷。
- 加：人物页写明来路（真人不标；推的履历写「照履历推定」；补的人标「虚构」）；每个政权后台记史料厚薄，厚的逐月、薄的大事照史书。
- 加：补书——十国春秋、九国志、两种南唐书、吴越备史、蜀梼杌、五代方镇年表、五代将相大臣年表等，先核能否取到干净全文。
- 命令：任务六改派 zcode（五代十国朝廷数据），新发任务七 zcode（游戏照表排朝堂）；Claude 审查，先审后唐、荆南两国样板。
