# 修 bug 先复现

## 步骤

1. **读清现象**：玩家原话、命令、`STATUS.md` 里有没有相关记录；在 `REQUIREMENTS.md` 搜相关 R-编号。
2. **定位**：用 `docs/知识库/架构.md` 的分区表 + `grep -n` 找到相关分区；顺着数据流（行动单 → 裁定 → 推演 → 记账 → 画面）找出错的那一步。
3. **写复现测试**：
   - 程序逻辑错：在 `web/tests/qa/` 新建或扩一条 Playwright 测试，造最小存档（`newSave({...})`），走到出错那一步，断言正确结果。
   - 文字规则错：加进 `web/tests/rules_cases.json`。
   - 提示词被改坏：加进 `web/tests/prompt_guard.js`。
4. **在旧代码上跑一遍，确认它失败**，把失败输出记下来（回奏时要贴）。
5. **改代码**：只改造成这个 bug 的地方；不顺手重构无关代码。
6. `python3 web/build.py`，再跑复现测试，确认通过；再跑 `prompt_guard`、`rules_regress`。
7. 把测试接进 `web/tests/qa.sh`（新文件才需要）。

## 检查

- [ ] 复现测试在旧代码上失败过（贴了输出）
- [ ] 修后通过（贴了输出）
- [ ] 同类入口都查过了（同一个错常在开局、读档、后台整理三条路上各出一次）
- [ ] 旧存档打开不报错

## 本项目踩过的坑

- 「点了没反应」常常不是按钮坏，而是被后台还没推好的资料挡住（R-144）：要查按钮的前置条件，并让它说清缺什么。
- 两个按钮共用一个内部标记，点 A 触发 B（R-189 查出「宣战」不宣战）：新按钮的标记要唯一。
- 要问 AI 的按钮，AI 出错时把异常抛到整页（R-189）：一律接住，说「这件没办成，再点一次」。
