# 交叉审查

## 步骤

1. 读命令文件和承办者的「回奏」。
2. 从对方的承办分支拉你的审查分支（如 `git checkout -b ds/review-1 origin/glm/task-1`），看改动：`git diff origin/claude/gallant-davinci-l8pni0...HEAD`。
3. **亲自跑测试**：至少 `python3 web/build.py`、`node web/tests/prompt_guard.js`、`node web/tests/rules_regress.js`、回奏里列的新测试。不要只信回奏里贴的结果。
4. 逐项对照下面的清单。
5. 新建 `中书省/审查/任务X.md`（格式见 `中书省/README.md`），每条问题写**在哪（搜索关键词）、什么问题、怎么复现、建议怎么改**；提交、推送你的审查分支。

## 清单

正确性
- [ ] 做到了命令「要做什么」的每一条
- [ ] 修 bug 的，有在旧代码上失败的复现测试
- [ ] 新按钮有真点测试；点了有真实后果
- [ ] 同类入口（开局、读档、后台整理）都改到了
- [ ] 旧存档打开不报错

规矩
- [ ] 只改了 `web/game.src.html`（及必要的测试、数据），没手改三个构建产物
- [ ] 数字、官职、关系由程序给，AI 格式里没有示例数
- [ ] 没有「某」「待查」「不详」、后世词
- [ ] 界面不露推演、把握、查证原文、内部标记、JSON
- [ ] 没删已有规矩、示范段落；`prompt_guard` 全过
- [ ] 没有 Key、模型型号名

范围
- [ ] 没越出命令的「改动范围」
- [ ] 没顺手大改无关代码

## 结论

全部打勾才写「通过」；有一条不过就「退回」，并写清要改什么。审查者不替对方改代码（除非命令这么派）。
