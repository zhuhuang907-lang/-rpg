# 写汇报

## 规矩

1. 照 `REPORT_EXAMPLE.md` 的格式。
2. 只用简体中文、玩家听得懂的话：**不出现**函数名、文件名、测试名、内部代号、英文缩写。
3. 写他能看到、能点到、能感觉到的变化，而不是代码怎么改。
4. 对照需求台账逐条说：做到了 / 没做到 / 未验证。
5. **没亲自验证的写「未验证」，不写「通过」**；依赖真 DeepSeek、真 GLM 的效果写「真模型下未验证，要你玩几回合看看」。
6. 坏消息照实说：测试没过就说没过、卡在哪。
7. 写完先自己改写一遍，确认不懂代码的人也看得懂，再发。

## 结构

- 第一句：这次做成了什么（或没做成什么）。
- 逐条：他提的每一点各一段，用他的说法。
- 要他做的事：比如「玩几回合朝局，看朝议表态的结果合不合理」。
