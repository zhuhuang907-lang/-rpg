# 接口与数据规范

> 这一篇管「程序和 AI 之间怎么交接」「存档里的东西怎么放」。违反它，游戏就会出现人人三十岁、官职含糊、钱粮乱跳这类老毛病。

## 一、程序定数，AI 填格

1. **数字由程序算**：钱粮、兵数、户口、年岁、品级、伤亡、胜负，由程序照存档和规则算出；AI 只能在程序给的格子里填文字，或给出程序会再核的建议。
2. **格式里不放示例数**：给 AI 的 JSON 格式只写字段名和含义，不写 `"age": 30` 这种样例（模型会照抄，出过「人人三十岁」）。
3. **AI 回来的东西一律过程序核**：
   - JSON 用统一的 `parseJSON`（搜 `function parseJSON`）读，读不出走既有的「再试一次」流程，不许把原文或 JSON 露到界面上。
   - 人名过真人年代关（搜 `R-209 真人硬门槛`）：已故超过四十年、尚未出生的不收；名单外夹带的不收。
   - 硬伤过常理审查（搜 `========== 常理审查`）：死人出场、一人两职、年岁离谱、钱粮为负、兵比户口多。
   - 兵马、地盘增加要有对应的令或战果（搜 `========== 收回账房的权`）。
4. **不写「某」「待查」「不详」**：查不到照任职时间线和制度推，标「约」或「推」，记进存档，之后照存档用，前后不矛盾（R-193）。

## 二、给 AI 的材料

- 材料由「账册 → 给 AI 的材料」统一拼（搜 `========== 账册 → 给 AI 的材料`），不要在别处另拼一份。
- 史实来源顺序：原文库 → 内置史料（`web/history`）→ 博查 → 维基；冲突以原文库为准（R-189）。
- 搜回来的东西先按年代筛（搜 `========== 搜回来的东西先按年代筛`），别的朝代、现代的一律丢掉。
- 推演结果、把握、查证原文、内部标记**只进材料，不上界面**。

## 三、AI 调用

- 调用一律走既有入口（搜 `========== 调 Claude`、`async function glmDirect`、`async function dsLookup`），不要新开一条直连。
- 每样活交给谁照设置（搜 `每样活交给谁`）；新加一类活，要在设置页那张表里加一行，并有默认值。
- 出错要有人话提示（`ERR` 表）和重试；不许把异常抛到整页上（R-189 修过一次）。
- 不在代码、提交信息里写模型型号名；Key 只存在玩家本机（`hrpg:dskey`、`hrpg:glmkey`、桌面版 `rpg-kernel/data/adapter-config.json`）。

## 四、存档

- 全局存档对象 `S`，由 `newSave({...})` 建（搜 `function newSave`）。
- 加字段：读的地方一律容错（用 `arr(...)`、`|| {}` 这类既有写法），旧档没有这个字段也不能报错；需要时在打开存档的地方补齐。
- 改字段含义：必须写迁移，并配一条「用旧格式存档打开」的测试。
- 存档不放 Key，不放整段搜索原文（大段原文进档案馆或缓存）。

## 五、史料数据文件

`web/history/*.json`：

| 字段 | 含义 | 规则 |
|---|---|---|
| `polities` | 本段的政权名 | `rulers[].polity` 必须在里面 |
| `rulers` | 君主：`name`、`polity`、`from`、`to`、`reigns`（`[年号, 起年]`） | 在位年不倒置；年号按起年排 |
| `events` | 史事：`y`、`m`（只记到季或年的写 0，程序按季末/年末排）、`text` | 不编造；有出处的写出处 |
| `figures` | 真人：生卒、官职 | 生卒不倒置 |

改完跑 `node web/tests/prompt_guard.js`，史料完整性那段会查。

## 六、命名与文案

- 界面文案只用简体中文、玩家听得懂的话；不出现英文、函数名、内部标记。
- 时代用语照 `========== 时代语言` 和称谓表（搜 `========== 称谓表`），不出后世词。
- 代码注释写清「为什么」：带 R-编号和玩家原话的要点（项目里的现有写法）。
