> 读者：要改代码的 AI。目标：十分钟内知道「要改的东西在哪、改了会牵动哪里」。
> 行号会随改动漂移，下面一律给**搜索关键词**，用 `grep -n '关键词' web/game.src.html` 定位。

## 一、一份源码，三个版本

```
web/game.src.html  ──python3 web/build.py──►  web/index.html               claude.ai 版（用浏览者自己的 Claude 账号）
   + 农历、史料、制度库、                     web/play.html                网页版（玩家自己的 DeepSeek Key）
     大势主线、舆图数据                        rpg-kernel/public/index.html 桌面版主页（配本机服务）
```

- **只改 `web/game.src.html`**。三个产物由 `build.py` 一次生成，版本号写进 `rpg-kernel/public/version.json`；提交检查会核对三份是同一次构建。
- `build.py` 嵌进去的数据（改这些 JSON 也要重新构建）：

| 占位 | 来源 | 内容 |
|---|---|---|
| `__CAL__` | `rpg-kernel/data/calendar.json` | 真实农历月表（前 221—1912） |
| `__HIST__` | `web/history/*.json` | 内置史事、君主年号、真人生卒官职（7 段：汉三国、晋十六国、晚唐、北宋、南宋金元、晚明、清中） |
| `__INSTLIB__` | `web/inst/*.json` | 各朝制度库（衙门、文书、称谓、易错处） |
| `__ARCS__` | `web/arcs/*.json` | 大势主线（按年月铺满的真实历史主线，分阶段） |
| `__VOCAB__` | `rpg-kernel/core/eraVocab.js` | 现代词 → 古代说法 |
| `__GEO__`、`__TERRAIN__` | `web/geo.json`、`web/terrain.json` | 舆图地名与地形 |
| `__ATLAS_*__` | `web/atlas/` | 历代疆域底图（1820、1911、海岸线等） |
| `/*__FACE__*/` | `web/face.js` | 画像生成 |

## 三、一回合怎么走

```
玩家下令（按钮或输入框）
  → 行动单（问/计/请/令/试）          ========== 行动单
  → 行动裁定（身份、权限、钱粮、制度） ========== 行动裁定
  → 查账（这一回要从账上查哪些）       ========== 查账
  → 原文库 + 联网查证（先原文库，再博查，按年代筛）
  → 推演（后台，不给玩家看）           ========== 推演模块
  → 写正文（storyRules 的铁律）       → 审校 → 常理审查（程序挑硬伤）
  → 记账（程序照推演结果改存档，数字由程序定） ========== 记账
  → 画面
  → 后台整理（朝局、天下消息、人物淡出……下一回之前做完）
```

要点：**数字、官职、关系由程序和存档定**，AI 只往定好的格式里填，程序再核（常理审查、真人年代关、账房收权）。

## 四、游戏里的 AI 分工（游戏运行时，不是开发分工）

需求台账 R-189、R-192：默认全交 DeepSeek，设置页可把「写故事、想事情」改给 GLM。

| 来源 | 管什么 |
|---|---|
| 原文库（`corpus/`，65 本正史、实录、通鉴、政书、兵书、地理书） | 史实第一来源：人名、官职、年月、典章 |
| 博查 | 联网找原文库没有的（地方小官、乡绅、商帮、考订文章） |
| GLM | 写正文、改稿；想天下大势、后果、市面民生、裁定、记账 |
| DeepSeek | 整理成表（官员表、行情表、核任期、核真人）；审稿；扮演敌国之主、大臣、朝臣互谋 |

互为后备：一家出错自动换另一家再来一次；材料太长先删中间；字数超上限减半再来。
网页版直连 GLM 会被智谱的跨域限制拦下（R-191），只有桌面版能用 GLM。

## 五、存档与本机存储

- 网页版：浏览器 `localStorage`，键都以 `hrpg:` 开头（`hrpg:save`、`hrpg:settings`、`hrpg:dskey`、`hrpg:glmkey`……）；claude.ai 版另存一份到账号，读取取新的。
- 桌面版：`rpg-kernel/data/`（`adapter-config.json` 放 Key，**不进仓库**）。
- 存档主体是全局对象 `S`，由 `newSave(...)` 创建（搜 `function newSave`）。改存档结构要考虑旧档：打开旧档时补齐字段，不能让旧档报错。
- 档案馆：每一回的完整正文另存，不受存档大小限制（`========== 档案馆`）。

## 六、桌面版 `rpg-kernel/`

- `server.js`：本机服务，托管 `public/index.html`，提供 `/api/*`（开局、回合任务、DeepSeek/GLM Key、原文库 `/api/histlib/*`、CBDB、CHGIS、网络自检 `/api/netcheck`、更新检查等）。路由表搜 `'POST /api/` 和 `'GET /api/`。
- `core/`：服务端模块（经济、档案、原文库检索 `histlib` 等）；`adapters/`：模型与检索适配。
- 打包：GitHub Actions「打包 Windows 版」（`.github/workflows/package.yml`），先跑快速质检，不过不打包；产物发到 Releases 的 `latest`。
