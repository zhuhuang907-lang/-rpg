# 测试标准

> 原则：**没有测试的改动不算做完**。测试要能在旧代码上失败、在新代码上通过。

## 一、三层测试

| 层 | 文件 | 跑法 | 管什么 | 多久 |
|---|---|---|---|---|
| 提示词护栏 | `web/tests/prompt_guard.js` | `node web/tests/prompt_guard.js` | 直接读 `game.src.html` 源码，查写正文的铁律、示范段落、格式规则、史料完整性有没有被改坏 | 几秒 |
| 规则回归 | `web/tests/rules_regress.js` + `rules_cases.json` | `node web/tests/rules_regress.js` | 正文清洗、替主角说话、擅自快进、官职含糊、夹英文、年代限制等程序规则 | 几秒 |
| 界面真点 | `web/tests/qa/*.js`（Playwright） | 由 `web/tests/qa.sh` 统一跑 | 打开构建好的页面，真点按钮、走流程，查存档、账目、页面报错 | 每个几十秒 |

完整测试：`QUICK=1 bash web/tests/qa.sh`（约一个半小时）。全过后它把源码指纹写进 `.qa-pass`，提交检查照这个放行。
两套完整测试不能同时跑；跑的时候不许重新构建。

环境：python3、node 22、playwright（`NODE_PATH` 指到它的 `node_modules`）、Chromium（`CHROMIUM` 指到可执行文件，不填用 playwright 自带）。
测试里的 AI、博查、维基、CHGIS 全是本机模拟服务（`web/tests/qa/ai.js` 等），**不连真模型、不花钱**。

## 二、写一条界面测试（照这个格式）

参考范例：`web/tests/qa/courtnow.js`（短，结构标准）。

```js
// 一句话说清防的是什么，带 R-编号和玩家原话的要点
const { chromium } = require('playwright');
const path = require('path');
(async () => {
  const b = await chromium.launch(process.env.CHROMIUM ? { executablePath: process.env.CHROMIUM } : {});
  const p = await b.newPage();
  const errs = []; p.on('pageerror', e => errs.push('page: ' + e.message));
  await p.goto('file://' + path.resolve(process.env.PLAY || path.join(__dirname, '../../play.html')));
  await p.waitForFunction(() => typeof 要测的函数 === 'function');
  // 1) 造一个最小存档：newSave({...})，只填这条测试要的字段
  // 2) 真点按钮：await p.click('...')；不要只调函数（硬规矩：每个按钮必须有真点它的测试）
  // 3) 查结果：存档字段、页面文字、账目；不对就 errs.push('哪里不对：' + 实际值)
  console.log('ERRS', JSON.stringify(errs)); await b.close();
})();
```

然后在 `web/tests/qa.sh` 里加一行 `run`（照已有的写），名字写清「防什么」：

```bash
run "一句话说清这条测什么（R-xxx）" 120 env PLAY="$ROOT/web/play.html" node 新测试.js
```

`qa.sh` 判过的标志：输出里有 `ERRS []`（或 `PAGE ERRORS 0` 等）；出现 `ERRS [` 后跟内容、`PAGE ERRORS 1+` 就判不过。

## 三、什么改动配什么测试

| 改动 | 至少配 |
|---|---|
| 新按钮、改按钮 | 界面测试里**真点**它，并查点完的结果 |
| 修 bug | 先写复现它的测试（旧代码上必须失败），再修 |
| 改写正文的规矩、提示词 | `prompt_guard.js` 加一项：防这条规则以后被删 |
| 正文清洗、文字规则 | `rules_cases.json` 加用例 |
| 史料 JSON（`web/history`、`web/inst`、`web/arcs`） | `prompt_guard.js` 的史料完整性那段能覆盖到；新字段要加检查 |
| 存档结构 | 测试里用旧格式的存档打开一次，不报错、字段补齐 |
| 桌面服务端 `rpg-kernel/server.js` | `rpg-kernel/test_runner.js` 能覆盖或新增 selftest |

## 四、模拟 AI 的局限

模拟 AI 只能测「程序有没有坏」，测不出「真模型写得好不好」。
所以汇报里凡是依赖真 DeepSeek、真 GLM、真博查的效果，一律写「真模型下未验证」，交给玩家真玩确认。

## 五、交测试结果的格式

原样贴命令和最后几行输出，例如：

```
$ node web/tests/prompt_guard.js
… 278 项全部合格
$ node web/tests/rules_regress.js
… 95 条全部合格
$ QUICK=1 bash web/tests/qa.sh
… 全部合格（或：哪一项不合格，原样贴出）
```

不许只写「测试通过」而不贴输出；没跑的写「没跑，原因：……」。
