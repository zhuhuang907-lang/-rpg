# 事件系统

## 与引擎的对接

`claude/history-sim-game-polish-txq63i` 分支的 `core/events.js` 已经把事件分成三类：**史事**（按史书排定、带日期与出处，条件不成立就不发生）、**天时**（按地域与季节掷年景）、**人事**（人物按史载卒年故去）。本规范沿用这三类，再补两类，一共五类：

| 类 | 来源 | 举例 | 依据要求 |
|---|---|---|---|
| **史事** | 剧本按史书排定 | 改元、新法颁行、大臣罢免 | 必须已核：日期、出处 |
| **天时** | 按地域与季节掷年景 | 旱、涝、蝗、丰 | 量级要合理；具体年份的大灾必须已核 |
| **人事** | 人物生老病死、升迁调动 | 某官调任、某长辈病重 | 史载人物必须已核；虚构人物由 GM 定 |
| **回响**（新增） | 玩家以前的决定 | 被你得罪的人找上门，你减的租引来邻家佃户效仿 | 必须能追到具体的哪一回合、哪一个决定 |
| **人群**（新增） | 人群满意度过线 | 佃户抗租、胥吏怠工、士卒鼓噪 | 必须能追到满意度的变化原因 |

## 史事怎么传到不同身份手里

同一件史事，对不同身份的到达方式、到达时间都不一样。这是"像崇祯模拟器那样有内容"的关键：大事不是旁白，而是**一份来报**。

| 身份 | 史事以什么形式到 | 延迟 |
|---|---|---|
| 皇帝 | 奏折、廷议 | 当回合 |
| 京官 | 邸报、同僚私语 | 当回合 |
| 地方官 | 邸报、上司札子 | 一到两月（按距离） |
| 军将 | 军令、塘报 | 视距离 |
| 商人、士子 | 传闻、邸报转抄、行市变化 | 一到三月 |
| 平民 | 里正、差役上门；坊间传闻；物价变化 | 数月；可能失真 |

例：熙宁二年九月颁行青苗法（已核）。皇帝是在廷议中拍板；杭州的周三娘是在几个月后，听里正说"官府要放钱给人户，春借秋还"。而且话会传走样。

## 事件卡格式

```
id: 唯一标识
类: 史事 / 天时 / 人事 / 回响 / 人群
标题:
何时: 具体日期，或"条件成立后第N回合"
条件: 什么情况下发生（不成立就不发生，历史因此分岔）
来报: 对玩家呈现为哪种来报（见 02 第二步），由谁带来
正文: 来报的正文（当时口吻）
牵涉人物: 引用人物卡
数值影响: 处理与不处理各自影响哪些数（区间，不写死）
后续: 可能引出的回响事件 id
依据: 已核来源 / 设定（写明）
仅GM: 真相、来报里的谎话、隐藏后果
```

## 人物卡（问人时用）

```
姓名 / 年岁 / 籍贯 / 身份
立场: 他站在哪一边、为谁说话
性格: 说话方式（一句示例台词）
私心: 他想要什么
记忆: 与玩家打过的交道（逐回合追加）
会出卖你的条件:
依据: 史载人物写出处；虚构人物写"虚构"，并标明 CBDB 同名核查结果
```

## 每回合的抽取规则

1. 先放到期的**史事**（条件成立的）。
2. 再放**回响**：上回合的决定，至少有一件在一到三回合内回来。
3. 再放**人群**事件（如果有满意度过线）。
4. 最后用**天时**和**人事**补满三到五份来报。
5. 同一回合里，同一人群、同一个人的事件不超过两件。

## 内容从哪里来

- 每开一个新局，GM 先做一张**本局史事表**：开局前后三年内会影响这个身份、这个地方的大事。每条带日期与出处，由引擎的档案馆记录。没核实的不进表。
- 地方的制度压力（赋役、科举、兵制、盐茶、契约），按朝代各列一张**制度清单**，作为回响事件和人群事件的素材。只有已核的条目能写进来报的正文。
- 虚构人物和虚构事件可以有，但所在的制度、物价量级、称谓必须合乎时代。拿不准就不写具体数，用"拮据""宽裕"这类词代替。
