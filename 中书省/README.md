## 怎么知道一件命令走到哪了（不用等 Claude 改状态）

先 `git fetch origin`，然后看远端分支：

| 远端有什么 | 说明 | 谁接着办 |
|---|---|---|
| 没有承办分支 | 还没人做 | 承办者开工 |
| 有承办分支，里面命令文件的「回奏」已填 | 已交 | 审查者审 |
| 有审查分支，`中书省/审查/任务X.md` 结论「退回」 | 要返工 | 承办者在原分支上改，改完在回奏末尾追加「第二次回奏」 |
| 有审查分支，结论「通过」 | 等 Claude 终审 | Claude |

## 承办者：回奏格式（写在命令文件末尾「回奏」一节，推到承办分支）

```markdown
- 承办：GLM / DS
- 分支：glm/task-1，最后提交：<提交号前七位>
- 改了什么：一条一条写，玩家看得懂的话
- 对应需求：R-xxx（逐条说做到没有）
- 新增或改动的测试：文件名 + 防什么
- 测试结果：命令和最后几行输出，原样贴
- 没做到 / 未验证：照实写（真模型下的效果一律写「真模型下未验证」）
- 改动范围：动了哪些文件、哪些分区
```

## 审查者：审查格式（新建 `中书省/审查/任务X.md`，推到审查分支）

审查分支从**承办分支**拉出来（这样你本地就有对方的改动可以跑测试）。照 `skills/交叉审查/SKILL.md` 逐项查，亲自跑测试。

```markdown
# 任务X 审查
- 审查者：GLM / DS
- 审的是：<承办分支> 的 <提交号前七位>
- 结论：通过 / 退回
- 问题：每条写「在哪、什么问题、怎么复现、建议怎么改」
- 我亲自跑过的测试：命令 + 结果
```

审查者只写审查文件，不替承办者改代码。
