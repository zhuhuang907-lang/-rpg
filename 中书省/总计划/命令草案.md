> ## 更正（2026-11-14 项目主人，R-231）——凡与下文冲突的，以这一节为准
> 项目主人原话：「做卡？我这是 rpg，做什么都可以，根本就没有固定的身份啊，可以随时切换，可以做所有」。
> 1. **没有固定身份，没有职业，没有“选一条线”**。玩家是一个人，想做什么就做什么，随时改行，可以同时是好几样（照 R-026 统一身份：当着官又是地主、带着兵又做买卖）。下文的「线」只是测试时走的几条路，不是给玩家的分类，界面上不出现「你是某某线」。
> 2. **「时代门路表」是世界的规矩，不是玩家的卡**。它只回答：在这个年代这个政权，一个人去投军、去应举、去做县令、去落草，世界怎么待他——台阶叫什么、凭什么上、谁管着他、会遭什么祸。玩家做到哪一步，程序就照表里对应的那一段回应；没做的不管。
> 3. **不拦、不锁、不设前置**。表里没写的事玩家照样能做，照自由输入的老办法裁定（看他的钱、人、权、名分够不够得着）；表只管「这时代有的东西长什么样、没有的东西不出现」。
> 4. **切换是重头**。验收不再是「每条线三种结局」，改成：任意两样之间能随时转，转了账接得上（兵、钱、人、仇家、名声都带着走）；同时兼几样时各样都照常运转。实玩打法里至少有三套是连转四五次的（如：农家子 → 投军 → 逃亡落草 → 受招安做镇将 → 入朝 → 自立）。
> 5. 开局的「你是谁」只是把此刻的处境说清楚（靠什么吃饭、上头是谁、眼下的难处），随处境变，不是定身份。

- 对应需求：R-229。分支 `zcode/task-roles`。
- 交：`web/roles/wudai.json`（之后 `sanguo.json`、`jin16.json`、`nanbei.json`、`tangmo.json`）。格式：

```json
{ "period": "wudai", "range": [907, 979],
  "cards": [
    { "line": "小兵|将领|地方官|百姓|起义|读书入仕|小宗室|王爷|贵族",
      "applies": "适用的政权或政权类别（如 中原五朝、南方诸国、契丹）",

      "ladder":  [ { "title": "台阶名", "leads": "管多少人或管什么", "by": "凭什么升到这一步", "how": "明载|推定", "src": "" } ],
```

## 丙线　五代十国身份线竖切（宰相办，一条线一个提交、一条线一份实玩记录）

每条线的完成定义相同：
- 开局到三种结局（出头、平庸、覆灭）都走得到，每个按钮有真点测试；
- 每月有照卡来的本分事和至少一件来自世界的压力（上头、同僚、钱粮、战事）；
- 身边十到二十个有名有姓的人，真人照表、补的人标虚构，各有所求所惧（见丁一）；
- 能转到卡里 `exits` 写的别的线，转了以后账接得上；
- 己一的真模型三十回记录交上来、对表过关。

### 丙一　小兵、将领
应募或被掠入伍 → 都里的日子（粮赐、操练、军法）→ 立功升迁（照卡的台阶）→ 被主将收为亲信或义儿 → 领一都、一指挥 → 出镇 → 随主上改朝换代，或拥兵自立，或被杀。朝代更替时站哪边，是这条线的大戏。

### 丙二　地方官（含幕职）、百姓上升、乱世起义
- 地方官：县令、刺史、节度使幕下的掌书记、判官、推官；钱粮催科、狱讼、镇将和牙校压着你、供军；考满迁转或随府主进退。
- 百姓：编户的赋役和灾年；投军、依附豪强、为吏、读书、经商各条路的门槛照卡。
- 起义：由头照这个时代的实情；聚众、粮、官军来剿、据州县称号、受招安成一镇或覆灭。

### 丙三　读书入仕、小宗室、王爷、贵族
- 读书入仕：应举的日子照史书；及第后的出路（幕职、州县、馆阁）；更常走的入幕与荐辟。
- 小宗室、王爷、贵族：照卡。五代宗室戏少，做到「有、对、能玩」即可，重头留给两晋南北朝。

## 丁线　文戏

### 丁一　在场人物的底成数据，写戏只用这些（宰相办）
- 做什么：
  1. 每个要紧的人在存档里有固定的几栏：所求、所惧、和主角的旧账（哪年哪件事、欠还是怨）、脾性两三个词、此刻的处境。真人照甲三的关系表和本传的结局写底；补的人照他的来路和位子由程序定，记死。
  2. 一回开写前，程序定下：这场戏在哪、谁在场、每人这场要什么。模型只拿这些写台词和神色，不许给人物添表上没有的亲属、官职、往事。
  3. 当面说、托请、宴集、书信、清议都走这一套；对方允不允，先由程序照所求所惧旧账和你给的东西算，模型演出来。
  4. 文人活动照时代门路表的 `scenes` 开（五代：入幕、投献诗文、荐辟；到两晋南北朝再加清谈、品题、雅集）。
- 完成定义：新测试——同一场戏重跑三次，在场的人、各自的要求、允不允一致；真模型三十回记录里，人物的亲属、官职、往事没有一处是表上没有的。

## 戊线　世界按月转、模型收口（宰相办）

### 戊一　朝局与军镇按月由程序转（先五代十国）
- 做什么：每月程序照固定规矩算：任满与出缺、病故（照年龄）、补缺（照资历、派系、主上亲疏）、弹劾与失势、节度使的叛服（照兵力、粮、与朝廷的亲疏、邻镇）、改朝换代的条件。原史是默认剧本：甲线表上写了的任免、叛乱、亡国，没被主角碰到就照表发生；主角够得着、真办了的才改道。
- 结果落到主角头上时，交给写戏的那一步成一场戏；不落到主角头上的只进见闻和年谱。
- 完成定义：不操作挂机十年，朝堂上的人逐年和表对得上（没被碰的位子一致率不低于百分之九十）；同一存档重跑结果一样；这一段每月不为朝局、军镇另调模型。

### 戊二　一百零二处调用列清单、逐批砍
- 第一步（阶段零就做）：交 `中书省/附件/模型调用清单.md`，一处一行：在哪个分区、干什么、归哪类（听懂玩家／写文字／演对方／其余）、「其余」的打算换成哪张表或哪条规矩、排在第几批。
- 之后每批砍掉的，在清单上划掉并写换成了什么、哪条测试看着。
- 完成定义：阶段三结束时 `plan_metrics.py` 的调用点数不高于四十；五代十国开局一回合里的调用只有三类。
