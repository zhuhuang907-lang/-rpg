> ## 更正（2026-11-14 项目主人，R-231）——凡与下文冲突的，以这一节为准
> 项目主人原话：「做卡？我这是 rpg，做什么都可以，根本就没有固定的身份啊，可以随时切换，可以做所有」。
> 1. **没有固定身份，没有职业，没有“选一条线”**。玩家是一个人，想做什么就做什么，随时改行，可以同时是好几样（照 R-026 统一身份：当着官又是地主、带着兵又做买卖）。下文的「线」只是测试时走的几条路，不是给玩家的分类，界面上不出现「你是某某线」。
> 2. **「时代门路表」是世界的规矩，不是玩家的卡**。它只回答：在这个年代这个政权，一个人去投军、去应举、去做县令、去落草，世界怎么待他——台阶叫什么、凭什么上、谁管着他、会遭什么祸。玩家做到哪一步，程序就照表里对应的那一段回应；没做的不管。
> 3. **不拦、不锁、不设前置**。表里没写的事玩家照样能做，照自由输入的老办法裁定（看他的钱、人、权、名分够不够得着）；表只管「这时代有的东西长什么样、没有的东西不出现」。
> 4. **切换是重头**。验收不再是「每条线三种结局」，改成：任意两样之间能随时转，转了账接得上（兵、钱、人、仇家、名声都带着走）；同时兼几样时各样都照常运转。实玩打法里至少有三套是连转四五次的（如：农家子 → 投军 → 逃亡落草 → 受招安做镇将 → 入朝 → 自立）。
> 5. 开局的「你是谁」只是把此刻的处境说清楚（靠什么吃饭、上头是谁、眼下的难处），随处境变，不是定身份。

## 二、总纲：这是一个 RPG，战略是它背后的世界

1. **一回就是主角的一场戏**。玩家是一个具体的人：有出身、有饭碗、有上头、有身边十几二十个有名有姓的人、有眼下的难处。国势、朝局、军务、舆图这些战略面板是他看世界、够得着时动世界的工具，不是游戏本身。
2. **身份 × 时代 = 一张卡**。同是「小兵」，曹魏的士家兵户、东晋的北府兵、北魏的六镇镇民、后唐的牙兵，入伍的路、往上爬的台阶、吃的粮、怕的事、能转去的身份全不一样。**每张卡是数据（带出处），程序读卡，模型不凭印象写。**
3. **这个时代没有的不许出现，有的不许缺**。三国没有科举（走察举、征辟、九品中正）；五代有科举但武人当国，出头多靠入幕、军功、做义儿。没有的写明「此时没有，替代是什么」。
4. **文戏是主菜**。每场戏里在场的人各有所求、所惧、和你的旧账（数据），模型只负责把它演出来。清谈、诗文、游学、入幕、上书、结社、说亲、托请，照时代开。
5. **战略系统重要，但在后台转**。朝局任免、军镇叛服、钱粮、战事由程序按月照固定规矩算，原史是默认剧本；它的结果落到主角头上时是一场戏（来人、原话、身边人的反应），不是一张报表。
6. 史料少的地方照 R-227 办：真人优先，位子搭全，补的人标虚构、记死。**门路表也一样分明载、推定两档，带出处。**

## 三、十条线（项目主人点名的）

文戏是贯穿全部的写法，不是一种身份；下面九种身份加「文戏」一条共十条。原有的君主、朝臣、商人、女子、江湖各线保留，照同一办法后补。

| 线 | 这条线要有的（每个时代各一张卡） |
|---|---|
| 百姓上升 | 户籍与身份（编户、佃客、部曲、兵户、杂户、奴婢）、赋役、灾年、能走的上升路（投军、依附豪强、读书、经商、为吏）和每条路的门槛 |
| 乱世起义 | 起事的由头（赋役、灾荒、宗教、兵变、流民）、聚众、粮从哪来、官府怎么剿、称号与建制、招安或覆灭 |
| 读书入仕（科举及其前身） | 这个时代真正的入仕路：察举、征辟、九品中正、门荫、科举、入幕；每一步的日子、考什么、谁说了算、寒门的天花板 |
| 小宗室 | 疏属的待遇、禁忌（禁锢、不得交通、典签监视、猜忌屠戮）、能做什么官、怎样自保或出头 |
| 王爷 | 封国与食邑的虚实、出镇与兵权、王府属官、和朝廷的拉扯、夺位与被废 |
| 贵族 | 这个时代的贵族是谁（门阀士族、侨姓吴姓、鲜卑勋贵、部落大人、沙陀武人世家、节度使子弟）、凭什么贵、婚宦、庄园部曲、衰落 |
| 地方官 | 县、郡、州、镇各级的本分事、上司与佐官、考课、豪强与胥吏、兵事来了怎么办、迁转 |
| 小兵 | 兵从哪来（世兵、募兵、征发、部落兵、牙兵）、编制与台阶、粮饷赏赐、军法、哗变与逃亡、凭军功出头的真实上限 |

| 文戏 | 在场的人各有所求所惧旧账；当面说、托请、清议、宴集、书信；每个时代的文人活动 |

## 五、阶段与过关门槛（**上一阶段没过关，不许发下一阶段的命令**）

每个门槛都是能数出来的数或项目主人的一句话，不接受「已完成」「大体可用」。

**阶段零　清障（一两天）**
- 项目主人定了扫描例外或换办法，zcode 能推上分支（待奏第四条）。
- 进度核对程序进巡查：每小时跑 `python3 scripts/plan_metrics.py`，数写进进度表。
- 一百零二处调用的清单做出来（戊二第一步），每处标：听懂玩家／写文字／其余（该由表或程序给）。

**阶段一　五代十国的底子**
- 朝廷数据：五代五朝、十国十家，加岐、燕（刘守光）、赵（王镕）、定难军、归义军、契丹共二十一个政权全在 `web/court/wudai.json`，数据检查全过。
- 厚的政权（后梁、后唐、后晋、后汉、后周、南唐、吴越、前蜀、后蜀）抽三个年份，每年明载加推定的在任者不少于六十人；薄的照史书有多少算多少，但位子搭全。
- 任职表复核：zcode 另抽一百条，错误率不高于百分之五。
- 时代门路表：五代十国一段九种身份的卡齐，卡检查全过。
- **项目主人验**：随便挑一个大国、一个小国、一个年份，看朝堂全不全、人对不对；看两张门路表像不像那个时代。原话记进进度表。

**阶段二　五代十国十条线竖切**
- 每条线：开局 → 至少三种结局（出头、平庸、覆灭）都走得到；每个按钮有真点测试。
- 真模型连玩三十回，正文里的人名、官职、年号对表，对不上的不超过百分之二；不出现这个时代没有的官名、物件、制度（照卡里的「此时没有」清单查）。
- 身份所在的那个政权，朝局和军镇已由程序按月转（戊一的最小一版）。
- **项目主人验**：十条线各玩一局，逐条说行不行。**不行的那条不算过，修到行为止；没验的不算过。**

**阶段三　模型收口**
- 五代十国开局下，一回合里模型调用只剩：听懂玩家的话、写正文、当面说里演对方三类；其余由表和程序给。调用点总数降到四十以下。
- 同一存档同一步重跑三次，账上的人、官、数一致（文字可以不同）。

**阶段四　照同一套铺开**：三国 → 两晋十六国 → 南北朝 → 唐末。每一段重复阶段一、二的门槛（政权表、朝廷数据、门路表、十条线、项目主人验）。两晋南北朝的小宗室、王爷、贵族三条线在这里做重。

**阶段五　收尾工程**：大文件按分区拆成多个源文件（构建仍出三个版本）；冻结的旧系统逐个定去留，报项目主人。

## 六、怎样确保执行到位

1. **数说话**。`scripts/plan_metrics.py` 每小时跑一次，出：模型调用点数、各政权位子与人数、门路表齐了几张、真模型实玩记录几份、台账里项目主人验过的条数。宰相把数抄进进度表，汇报里带上和上一次的差。数没动就是没干活，不许写「在推进」。
2. **过关只认三样**：检查程序的输出原样贴出、真模型实玩记录进了仓库（`中书省/附件/实玩/`，不含 Key）、项目主人的原话。三样缺一样，进度表那一格不许写「过」。
3. **一件命令一个可查的完成定义**。命令草案每件都写了「交什么文件、跑什么检查、数到多少」。回奏不贴检查输出的，宰相直接退回。
4. **小批交活**。zcode 每做完一个政权或一张卡就提交推送；宰相每小时审到哪批批到哪批，不等全做完。
5. **zcode 的活只给数据和跑测试，不给它改大文件**。一万六千行的源码由宰相改；zcode 上回抽查做得准（查出 27.6% 的错），照这个长处用它：摘史料、抽查、在项目主人电脑上跑真模型实玩。
6. **zcode 推不上来时的退路**：扫描的事项目主人没定之前，zcode 把做好的数据文件直接交给项目主人，由项目主人在宰相那场对话里贴路径或上传；或者宰相自己做甲线、等 zcode 通了再交回。不许因为这一条整条线停着。
7. **宰相自己也受这张表管**。连续两次巡查进度表没有一格变化，宰相要在汇报第一行写明卡在哪、要项目主人定什么。
8. **不加新功能**。阶段二过关以前，除了这份计划里的，不接新系统；项目主人新提的要求照旧入台账，排进对应阶段。
